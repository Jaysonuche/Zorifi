signInWithGoogle(), getIdToken() and authenticatedFetch() use Firebase Identity

<localId>::<projectId>::<assetId>. No Studio project file/media upload was added.

IMPLEMENTED INTEGRATION (PHASES 2–4)

The existing floating orb, shared inspector/chat, first-use introduction, optional
idle assistance, opt-in microphone/wake mode and ElevenLabs playback remain in
use. There is no standalone demo or duplicate editor state. Idle help is scoped
to active editor projects. Microphone/wake starts disabled unless that account
previously enabled it.

New zorifi-vanessa-production.js provides the authenticated conversation/proposal
bridge and window.ZorifiEditorStore as a facade over the existing live state.
New zorifi-timeline-edit-api.js supplies shared native split and trim primitives,
used by both manual editing and the validated Vanessa adapter.

Pipeline: instruction -> authenticated POST /api/vanessa/chat -> server provider
interpretation -> allowlisted structured proposal -> strict client validation ->
review and Apply for split/trim -> existing editor mutation/history -> actual
timeline verification -> local save/readback -> truthful assistant result.
Supported initial commands: clip.split, clip.trim, history.undo, history.redo,
project.save. Unsupported parameters, arbitrary code/state fields, nonexistent
clips, locked tracks, automatic endings and invalid source bounds are rejected.
Split/trim preserve independent nested clip data, bound animation to the retained
window and clamp fades. The playhead remains at its actual timeline time.

Pending proposals are bound to the Firebase session, local account, project,
view, selection and timeline revision. A stale proposal or navigation during
authentication fails before mutation. Stop invalidates proposals and aborts
pending requests. Completed synchronous mutations require Undo to reverse.
Save failure rolls back the edit; a second persistence failure is reported as an
unsaved rollback instead of claiming everything was saved.

New backend files:

The route verifies Firebase identity and binds sessions to that UID/project ID.
Firestore sessions: /users/{uid}/sessions/{sessionId}.
Durable quota: /users/{uid}/vanessaLimits/chat, 20 requests per 60-second window.
Compare-and-set writes enforce ordering and concurrent-request exclusion.
Request hashes bind retry IDs to the original input. Stored response signatures
use a server-only HMAC key, domain-separated from other uses; altered replies
cannot be replayed as valid provider proposals. An optional stable
VANESSA_SESSION_SIGNING_KEY is documented in .env.example; otherwise the existing
text-provider key signs responses. Credentials never enter browser bundles.
Quota storage failure fails closed; there is no process-memory quota fallback.

The loopback authentication exemption and local-password sign-in fallback were
removed. Firebase-verified legacy profile linking remains. Provider cancellation
signals now propagate through auth, HTTP adapters, text and speech requests.
Rate-limited text routes have a 105-second budget to reserve host cleanup time.
Electron routes /api/vanessa/chat through its fixed hosted relay with the user's
Firebase bearer; local provider keys cannot replace that private session route.
Capacitor builds target Zorifi's fixed HTTPS chat route with authenticated CORS.
Busy requests are rejected explicitly instead of silently discarded. Request
controllers/listeners and bridge lifecycle hooks are cleaned up.

REMAINING LIMITATIONS AND DEPLOYMENT

1. Publish approval is required for the staged Firebase rules before deploying the
   application. The staged text exactly matches tested firestore.rules. Existing
   published rules were compared with repository HEAD before adding the two new
   private paths. Production access behavior has not yet been exercised.
2. Device-only projects have no authoritative server document. The server verifies
   authenticated workspace/session binding; the client checks actual local state.
   It cannot independently verify the provenance of local media or project files.
3. Provider/auth browser responses were controlled fixtures; no paid live Gemini
   or ElevenLabs request was made. Credentials, provider availability, quotas and
   model access can still fail and are surfaced as errors.
4. The durable chat route returns complete JSON replies; the legacy SSE endpoint
   remains available. Word-accurate speech alignment is not claimed: the existing
   ElevenLabs response has no word timestamps. Captions track actual speech state.
5. Cloud sessions keep bounded recent context and the last signed reply, not an
   unlimited transcript archive. Clearing the current conversation removes its
   cloud session as well as the corresponding local UI conversation.
6. Undo stacks do not survive refresh; committed edited project contents do.
   Trimming/splitting synthesizes boundary keyframes; it does not promise identical
   mathematical Bezier subcurves for every complex custom easing case.
7. Web behavior and the desktop cloud relay were verified. No native packaging,
   installed Electron UI, or physical iPhone microphone/installation behavior was
   verified in this pass.
