Existing architecture
app.js owns state, render(), snapshot()/pushHistory(), undo()/redo(), native
vanessaActionAdapter({project,detached}), saveProject()/loadProject(), local
project/media persistence, and the editor's real tool catalogues. The Stage 2
registry is a validator/description/postcondition layer; it creates no store.

zorifi-vanessa-professional-tools.js discovers 98 logical tool entries across 21
categories. 43 actions can run on a staged copy of the real project and be
verified before one native commit/checkpoint. 55 entries expose existing
workflows with their implementation and recovery requirements; they are NOT
advertised as automatic batch actions. The registry does not pretend provider
configuration or a tool button is proof that a provider job completed.

The existing recipe registry, zorifi-tool-registry.js, describes 13 renderer
operations plus saved validated data recipes. It is retained. Its captions and
transitions are AutoCut renderer treatments rather than replacements for the
editor's native text and transition systems.

Safe batch action contract
  {command, target, parameters}; no arbitrary properties, eval, JS or state patch.
  clip.add: stable id/mediaId/start/duration + optional sourceStart, typed track,
  volume, playbackRate, fit. Real available source and bounds are required.
  text.add: stable id/text/start/duration + optional typed track, registered fontId,
  fontSize/fontWeight/colour/position. Later actions may target the stable ID.
  120 action upper bound, with per-step structure and live staged-state validation.
  Reference IDs, parameter types/ranges, tool availability, lock state, automatic
  endings, source bounds and clip-type compatibility are checked before execution.
  actionSchema({catalog}) supplies bounded known action shapes for Gemini.
  validateStructure is server-safe; validateAction adds actual project checks.
  verifyAction checks the expected native editor state after each operation.
  Registry metadata requires authenticated project scope and review/checkpoint;
  the orchestrator must enforce identity, confirmation, cancellation and save.
  Async/global UI actions cannot run through this staged-batch validator.

Limits

  55 workflow entries require their existing dedicated UI/service execution and
