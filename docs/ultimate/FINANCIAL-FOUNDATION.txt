Verified implementation
The existing OpenAI token allowance remains untouched. A separate server-only
financial foundation provides the missing monetary reservation and customer
credit semantics. It is not wired to provider endpoints or client billing UI.

Free, Pro and Nexus are the only tiers. Standard, Advanced and Nexus are the
only reasoning modes. A trusted server subscription resolver is mandatory;
unverified plans fail closed and expired paid subscriptions revert to Free.
Purchased credits cannot enable a subscription-only capability.

Preview policy contains the proposed 1/3/6 daily local music generations,
5/15/30 monthly unique-song unlocks, and 60/180/600-second duration limits.
Free receives the proposed 15 daily Vanessa request units. Other included
wallet allocations require explicit server configuration. These are testable
preview policies, not active commercial offers. Duration is refused explicitly
when over the tier limit; it is never silently shortened.

Four wallets: Vanessa, Image, Video and Vocal. Included allowance is reserved
first, then purchased balance. Purchased balances have no automatic expiry.
Sandbox grants are disabled by default and require an explicit local test flag;
live payment grants are always rejected. Receipt IDs cannot be replayed for a
different account, wallet, amount or currency. This is not a payment adapter.

SQLite BEGIN IMMEDIATE transactions protect budget, wallet and allowance changes
across multiple connections. Integer GBP micro-units are used throughout, with
a default shared monthly cap of 15,000,000 (£15); configuration may lower it,
not silently raise it. There are no live provider prices in source. A verified
server price catalog must contain a worst-case cost before paid work can reserve.
The test catalog uses conspicuously synthetic prices only.

Every request has an account-scoped idempotency key and server-computed content
hash. Retry with a different input/price/quantity is rejected. Actual provider
cost settlement is idempotent. Failed/cancelled work refunds customer credits
while retaining actual provider charges against the platform budget.

Cancel before dispatch refunds held credits and budget. Cancel or lease expiry
after dispatch retains both until trusted usage reconciliation. Unknown charges
cannot be erased by a timeout or a restart. All outstanding cost holds reduce
the current month's budget, including those originating in an earlier month.
Reconciled cost is conservatively recorded in the reconciliation month. This
internal ledger is not represented as the provider's billing invoice.

An actual cost above its reserved maximum is recorded truthfully and persists a
spending halt. The foundation cannot reverse an already incurred provider bill;
production requires bounded provider requests plus verified maximum-cost quotes.
No provider alerts or lagging invoice estimates are described as a hard stop.

Song identities are unlocked once per account after verified successful export.
Batch exports reserve all new songs atomically, repeated/previous-month songs
cost no second unlock, concurrent exports cannot double-charge, and failed
artifacts release reservations. Pending export IDs survive restart and appear
in the account summary for recovery. A lost export is never silently reported
as successful or automatically charged as a completed unlock.

Local tests performed
23 tests passed with real Node SQLite databases, including two simultaneous
connections, close/reopen persistence, cross-account lookups, cancellation,
refunds, month rollover, Pro/Nexus restrictions, exact-duration refusal,
multi-song unlocks and sandbox receipt replay prevention. A read-only review
identified a delayed entitlement lookup crossing the month boundary; this was
fixed by sampling time and evaluating expiry inside the transaction after the
lookup. Regression tests also verify that expired holds cannot be dispatched.
No paid API calls,
Firebase changes, emulator claims, provider billing tests or deployments made.

Production gaps / mandatory next boundaries
1. Authenticated routes must obtain UID from verified Firebase Authentication.
   Never accept UID, tier, content hash or measured actual cost as client authority.
   Validate ownership and provenance of canonical song IDs and successful export
   receipts before reserving or completing song unlocks.
2. resolveEntitlement must read server-owned records with subscription expiry;
   current PRO-only legacy resolver is not automatically upgraded by these files.
3. A durable privileged transactional hosted adapter is still required. The
   provided local factory explicitly refuses Vercel/Netlify/production/remote
   origins. No ephemeral hosted SQLite or per-user bearer global ledger fallback.
4. Every billable provider must reserve before dispatch and reconcile trusted
   usage. Existing provider endpoints are not yet covered by this foundation.
5. Live catalog prices, FX safety margins, payment signature validation, refunds,
   chargebacks, approved subscription offers, hosted dashboards and admin tools
   remain unfinished. No live prices or checkout have been activated.
6. Client-only local music and export can be used offline; a local foundation
   test does not claim tamper-proof remote enforcement of offline client actions.
7. Pending paid/export work requires a recovery coordinator. Unknown provider
   usage remains held until reconciled, potentially blocking further work.
8. Replacement credentials, exposed-key revocation and protected preview gates
   still apply. No paid service or Firebase upgrade is needed for these tests.
