NATIVE INSTRUMENT AMPLITUDE LFO — PART8/10/14/16
The optional pattern.amplitudeLfo object has exactly five fields:
 {waveform:'sine'|'triangle',clock:'hz'|'beats',rate,depth,phase}
Hz rate is0.05–20. Beat-clock rate is a period of0.125,0.25,0.5,1,2,4,8 or16
quarter-note beats at the source pattern BPM. Depth is0–1; phase is0≤degrees<360.
The native edit uses:
 {operation:'amplitudeLfo',amplitudeLfo:{waveform:'sine',clock:'hz',
   rate:4,depth:.4,phase:0}}
Reset uses amplitudeLfo:null and removes the optional field. Repeating identical
settings/resetting an unconfigured source refuses as a no-op. Unknown fields,
invalid clocks/waves/non-finite/out-of-range values refuse before rendering.

The LFO attenuates the mixed native source after its original tanh saturation and
before its existing end fade. Its source-pattern clock continues across notes;
it does not restart at each note onset. Phase0 starts at the original level and
phase180 at minimum. Depth0 leaves the original sound unchanged; depth1 can reach
zero, with no signal boost. Sine changes smoothly; triangle uses linear ramps.
Each existing instrument carrier, ADSR, note/MIDI timing, source duration, voice
budget, clip source trim/rate, mixer, effects and source-parent history remain.
Clip playback rate naturally changes playback of the rendered source clock; this
is not a separate project-clock/pitch-preserving modulation system.

Collapsed source-note controls and the reviewed native-music bridge use the same
music.native.edit operation, worker rendering, source replacement and one Undo/save.
The active crossfade source-change guard remains: reset the pair before replacing
its native source. Composition and timeline locks still refuse changes. Source
files are rendered locally; no provider or licensed external sample is requested.

Vanessa grammar examples:
 Set native tremolo sine 4 Hz depth 40% phase 0 degrees
 Set native tremolo triangle every 1 beat depth 50%
 Reset native tremolo

Nine focused LFO units pass. They verify optional data round-trip, independent
PCM attenuation for both waveforms at22050/44100/48000Hz, source-clock phase/depth,
beat periods/BPM, no extra source voices/tails, malformed/no-op/lock cases, reset
and zero-depth parity, unchanged MIDI and21 pre-LFO legacy hashes across seven
instruments and three sample rates. Actual worker/UI/outer Vanessa, saved reopen,
scopes/locks/history and decoded MP4 browser proof also passes.

This is amplitude tremolo, not pitch vibrato, filter LFO, a general modulation
matrix, wavetable/sample design, SoundPrint, Sound Fusion or timbre transfer.
The Instrument Lab master requirement stays Partial; raw LFO row0389 advances
only to Partial based on the bounded implementation and focused tests.

EXPLICIT COMPATIBLE PATH-ANIMATION COPY — PART25
The existing animation.copy operation retains scalar-copy parameters and adds:
 {sourceId,properties?,at?,expressions?,
  morphs:[{sourceGroupId?,targetGroupId?}]}
Up to33 explicit path mappings are accepted; an omitted group ID means the main
editable path. Group names are not guessed. Each target path appears only once.
A source morph may be copied into more than one explicitly selected target path;
the copied channels are independent, not aliased. Scalar-only copies now leave
existing path morphs intact instead of refusing merely because a layer has them.

Requested morph channels clone corresponding literal vertices, incoming/outgoing
Bezier handles and easing. Their key times shift by(at or target.start) minus
source.start in the target's containing composition clock. They are not scaled,
cropped or resampled; all copied morph keys must fit the target layer duration
and the existing0–86400 clock bounds. Matching point count/order and open/closed
topology are required. Explicit main→group, group→main and group→group mappings
are supported when their existing geometry is compatible.

Only requested target morph channels and selected scalar channels are replaced.
The target's original base geometry, paint, layer timing/transforms and unmapped
animation remain editable. Existing optional scalar-expression copying retains
its route. Malformed/duplicate mappings, missing source channels, incompatible
topology, locks/protected containing tracks and whole-project key/vertex/render
budgets fail on the draft before any project mutation. Source layers stay unchanged.

Collapsed Motion Scenes controls expose source layer, placement, scalar/expression
options and one explicitly chosen source-path→target-path mapping. The same
operation is available to reviewed Vanessa through motion.edit/dataJson. All
existing dataJson transport and graph limits remain. Eleven focused tests pass,
including clock/paint/mask preservation, main/group mappings, isolation, failures,
budgets, nested source clocks and exact professional-tool postconditions.
Actual UI/outer-confirmation/pixel/MP4/reopen browser proof passes with no browser
exceptions or live provider calls.

This does not infer topology, normalize differently sized shapes, copy arbitrary

EQUAL-POWER CROSSFADE CURVES — PART12/20
audio.crossfade.apply adds optional curve:'linear'|'equal-power'. The existing
root-pair source/track/boundary/overlap0.01–30s/lock/collision/dependency guards
remain. Later clips do not ripple, and the incoming clip still moves earlier.
Only the inner outgoing/incoming fade curves change. Existing outer fades,
source windows, key/caption shifting, re-edit/reset and one Undo/save remain.

The shared AudioEngine.fadeGain evaluates optional audioFadeInCurve and
audioFadeOutCurve. Equal-power gain is sine(pi/2×progress); the outgoing fade's
remaining progress gives its complementary cosine. Across the overlap the
squared gains sum to one, with both midpoint gains about0.707. Default/legacy
fades stay exactly linear. These same native fields feed preview, offline PCM,
WAV and MP4 audio rather than a disconnected crossfade preview.

Existing version1/default-linear pair records stay readable. Explicit curves use
version2 metadata with a validated curve and expected source/timing/fade records.
Updating/restoring a pair preserves its original curve fields, including whether
a field was originally absent. Reset restores original fades/curves and boundary.
Changed or malformed pair records refuse atomically instead of overwriting edits.

The manual selector and reviewed Vanessa share the same native operation.
An explicit request can choose either curve; an omitted curve preserves the
existing pair's choice or defaults to linear for a new pair. UI/review warn that
correlated recordings can still raise the combined peak. Constant squared gain
does not guarantee constant perceived loudness or prevent clipping/master gain.

Eight new curve units and28 existing crossfade units pass. Actual new browser
proof passes with real source tones, manual curve selection, outer Vanessa
review/decline/apply, exact native preview law, measured stereo PCM, one Undo/Redo,
save/reopen/reset and320/390/768/1440px controls. The actual encoded/decoded MP4
retains the equal-power two-tone relationship; no sample-exact recorder clock is
claimed. The recorded AAC normalized squared-gain sum is about0.995 and the
measured late gap is silent. Artifact: artifacts/editor-crossfade-curves-browser.json
and artifacts/equal-power-crossfade.mp4. No browser exceptions/provider requests.

This does not extend source handles, analyze correlation automatically, implement
ripple arrangement, full DAW buses/sends, LUFS/true-peak or mastering.
