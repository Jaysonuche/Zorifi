TONAL SINE PITCH VIBRATO — PART8/10/14/16
Optional pattern.pitchVibrato has exactly four fields:
 {clock:'hz'|'beats',rate,depthCents,phase}
Free rate:0.05–20Hz. Beat rate is a period of0.125,0.25,0.5,1,2,4,8 or16
quarter-note beats at the source pattern BPM. Depth is0–100 cents and phase is
0≤degrees<360. The edit uses existing music.native.edit with:
 {edit:{operation:'pitchVibrato',pitchVibrato:{clock:'hz',rate:5,
   depthCents:25,phase:0}}}
Reset uses pitchVibrato:null and removes the optional pattern field. Identical
settings, invalid fields/bounds or resetting an unconfigured source refuse as
no-ops/errors before rendering. Bass, piano, pluck and pad are supported. Remove
pitch vibrato before selecting percussion; it is not a drum pitch effect.

The instantaneous frequency ratio is2^(depthCents*sin(source-phase)/1200).
The engine integrates this ratio using a six-harmonic Fourier/Bessel kernel,
then applies the resulting time only to oscillator carrier phase. It does not
multiply frequency by elapsed time discontinuously. The source modulation clock
continues across notes while each note retains its original carrier reset and
ADSR/decay timing. No duration-sized phase buffer, added voice or note/source
tail is created. Original source/MIDI timing, notes, amplitude LFO, envelope,
clip trims/rate, mixer and effects remain independent.

Absent/zero-depth/reset paths retain the original synthesis arithmetic and exact
PCM. The original source replacement/parent metadata, worker, composition/track
locks, crossfade source protection, guarded scope and one Undo/save are reused.
Collapsed manual controls and reviewed Vanessa use the same native edit.
Example local commands:
 Set native vibrato 5 Hz depth 25 cents phase 0 degrees
 Set native vibrato every 1 beat depth 50 cents
 Reset native vibrato

Ten focused units pass, including independent numerical integration/PCM checks
at22050/44100/48000Hz, rate/depth extremes, late source clocks, high MIDI pitches,
zero/reset/legacy hash parity, percussion/lock/no-op refusal and unchanged budgets.
The actual browser proof passes manual and outer reviewed Vanessa/cancel/withhold,
worker PCM/MIDI/source-parent history, locks/crossfade/Stop/stale scopes, saved
reopen and dark/light320–1440px controls. Source audio remains actually modulated
in decoded MP4 under both export pitch policies. No paid provider calls or browser
exceptions occurred. Artifact: artifacts/native-vibrato-browser.json.

This is bounded sine vibrato on four native tonal voices. It is not pitch
correction, filter modulation, a general modulation matrix, realistic vocal
generation, a sample/wavetable designer, timbre transfer or full Instrument Lab.
Only raw Advanced modulation row0386 advances to Partial, not a whole master area.

BOUNDED LINEAR SOURCE-TIME AUDIO — PART8/20/25/38
ZorifiOfflineMix now accepts covered strictly increasing linear sourceTime keys
on leaf audio/video recordings. Existing native keyframe controls and reviewed
motion.edit / animation.keyframe remain the authoring APIs. Key time uses the
containing composition clock; key values are source positions. Constant-rate
nested containers provide affine child-to-root clock mapping.

The planner schedules one continuous native AudioBufferSource and one existing
DSP chain per audible source, with piecewise-constant playbackRate events at the
linear remap knots. It does not restart EQ/compression/limiter state per segment,
manually interpolate raw PCM or create a second timeline. Source offsets/end,
cropped ranges, inherited gain/pan/fades and existing output length remain native.

Limits and refusals:
-2–65 keys per remapped layer; at least10ms between root-clock knots.
-Strictly increasing source values and linear outgoing easing; no active temporal
 Bezier interpolation. Inert Bezier metadata authored by the native linear-key UI
 does not turn a linear key into a curve.
-Combined forward rate0.0625–16 and local slope≤16.
-At most2048 remap rate events per mix; lower custom limits remain enforceable.
-Existing600s output,64 audible sources,64MiB/source and128MiB total encoded,
 256MiB decoded,128MiB stereo output and1,200,000 automation-evaluation budgets.
-Keys must cover the audible exported window. Holds, backward positions,
 uncovered/extrapolated windows, nonlinear/speed ramps, simultaneous rate keys or
 timing expressions and remapped nested containers refuse rather than export
 incomplete audio. Intentionally muted unsupported clocks remain silent; globally
 invalid graph metadata still refuses.

Native playbackRate is treated as128-frame k-rate scheduling. Event-grid delay
and float-rate quantization are bounded conservatively to≤5ms source-clock and
≤10ms output-clock error at the chosen sample rate. Plans exceeding that budget
refuse and suggest simpler/aligned keys or48kHz. This is bounded native scheduling,
not sample-exact audio. Supported PCM sample rates remain16000/22050/44100/48000;
plan defaults48000 and render passes the actual chosen rate to its checks.

Primary scheduling reference, verified28November2026:
https://www.w3.org/TR/webaudio-1.1/ (22September2026 Working Draft).
The specification defines buffer-source rate parameters as k-rate, sampled at
the start of a render quantum, and the default offline quantum as128frames.
Its buffer-source duration argument measures source-buffer seconds independently
of playback rate. These definitions inform the bounded scheduler; the independent
actual browser/PCM measurements below establish this implementation's behavior.

Review found a plan/render mismatch in sufficiently slow nested clocks:10ms root
knot spacing can become too dense for the native graph's local derivative check.
The planner now verifies native source clocks/rates at every remap interval before
opening a decoder or reading media. The renderer skips duplicate remap checks.
The workload budget includes twice the remap interval count for validation and
possible new automation samples. Constant-only workload thresholds stay intact.
An exact slow-nesting reproduction now refuses during planning, and a boundary
workload test preserves the old constant plan while rejecting excessive new work.

Previously successful constant-rate segment objects and source.start duration
arithmetic stay unchanged, including floating-point-sensitive source offsets.
Nonempty speed presets and rates below the native constant clock's0.05 minimum
now refuse early rather than reaching a later inconsistent render. Source bytes,
Stop/account/revision checks and existing cleanup/memory bounds remain. Native
decode/render may finish after Stop; late results are discarded.

Thirteen new remap and eight legacy focused units pass. They cover exact source
clocks/crops/nesting, source bounds, invalid keys/holds/precision/event/workload
limits, one continuous source/chain, constant arithmetic and early native-clock
refusal. Actual browser proof also passes: manual three-key authoring, two outer
Vanessa fixture turns, decline/withhold/confirm, Undo/Redo/reopen/Stop and real
PCM/WAV/MP4 source events. It is not inferred from the unit results.

EXPLICIT VIDEO-EXPORT AUDIO PITCH — PART8/20/25
Investigation separated two existing policies: video export used HTML-media
pitch preservation while WAV used rate-changing native buffer playback. This
phase keeps the old MP4 default and makes the choice explicit instead of silently
changing existing video output.

The Export video controls offer Audio pitch:
 preserve — Keep source pitch (legacy default)
 speed — Pitch follows speed (like the WAV policy)
The selected value is proSettings.exportAudioPitch. Existing export.prepare can
prepare audioPitch:'preserve'|'speed'; validation rejects other values. The local
Vanessa command “Open export with pitch following speed” opens the real control
with the matching choice. Preparing settings is not exporting a file.

setExportAudioPitch uses preservesPitch or the supported moz/webkit property,
checks the applied readback and fails clearly for unsupported explicit speed-linked
requests or refused settings. The UI disables the unavailable speed option when
the browser cannot expose pitch control. A later saved project/reopened dialog
retains the selected choice. This changes export policy, not the native source,
MIDI, timeline duration or live-preview default. Active non-frozen speed-linked
combined rates must be0.0625–16; unsupported requested rates refuse instead of
silently clamping the chosen pitch policy.

Three focused export-policy units pass. Actual browser manual/Vanessa preparation,
responsive controls and saved reopen pass. Two real decoded MP4 outputs from the
same clip at1.1× demonstrate the policy difference:
 Keep source pitch: observed upward464.75Hz and downward416.5Hz.
 Pitch follows speed: observed512.25Hz and457.25Hz.
 Offline PCM: observed512.5Hz and457.25Hz.
The source vibrato remains audible in both files; speed-linked output follows
the WAV pitch policy. This does not certify sample-exact MediaRecorder/AAC timing
or every browser's pitch-correction quality. WAV remains source-rate/pitch-changing.
