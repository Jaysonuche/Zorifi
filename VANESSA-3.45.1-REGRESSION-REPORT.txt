WHAT WAS REPRODUCED

1. A blank, unusable Vanessa inspector at ordinary laptop/window widths.
   In the actual installed Zorifi window (approximately 1040px wide), the Vanessa
   tab was selected and accessibility exposed its messages and input, but the
   whole conversation area was visually blank. The local browser reproduced
   height 0 for #editor-inspector-content, .vanessa-inspector-host and .vanessa-panel
   at 1024/1040px. At 1440px it had positive height and worked.

   Cause: styles.css only supplies display:grid to the desktop inspector above
   1100px. The Vanessa-specific rule in zorifi-vanessa-chat.css specified grid
   rows but did not enable grid. Its absolutely positioned conversation collapsed
   inside a zero-height container. The rule predates 3.45.0 (87243dc); it was not
   newly introduced by 74237eb. Earlier 1440px browser checks missed this defect.

   Fix: explicitly apply display:grid to the active desktop Vanessa inspector.
   Regression: actual Send/reply and dimensions at 1024/1040/1100/1440px, both
   Chromium and Windows WebKit, with safely reported storage failures.

2. An open installed app running stale JavaScript after deployment.
   The installed app lacked Recover workflow and showed receipt wording from the
   older implementation, despite the public 3.45.0 files matching the new source.
   A worker can claim an already-open page without replacing its in-memory JS.
   The application previously had no update/controllerchange notice.

   Fix: new worker installations/controller changes offer Save and reload. This
   never auto-refreshes a running edit; it refuses reload during an active Vanessa
   request, unfinished imported-media persistence or a failed project save. Device
   projects and IndexedDB are preserved. An already-open pre-fix app still needs
   one manual refresh to load the new notice and corrected client.

3. Unsafe release-cache behavior and HTML returned for failed scripts.
   sw.js deleted every previous/unrelated cache on activation and used index.html
   as a fallback for any failed asset fetch. A missing JavaScript resource could
   therefore become HTML and raise an Unexpected token '<' import error. Retaining
   an old cache also exposed an offline-navigation issue: global caches.match
   selected the older index instead of the newly installed shell.

   Fix: verify script/CSS/JSON response types, refuse invalid precache responses,
   cache successful complete resources only, keep one previous release for open
   clients, preserve unrelated caches, and restrict offline HTML navigation to the
   current release cache. APIs/auth remain uncached. Failed assets fail honestly.
   A real Chromium worker-install/update/offline test verifies the old running
   release remains usable and offline reload chooses the complete new shell.

4. Background cancellation of ordinary replies.
   zorifi-vanessa-production.js previously cancelled ALL requests on hidden-page
   events, including plain conversation. The existing installed conversation
   contained the raw failure 'signal is aborted without reason'. That message is
   consistent with the old cancellation path, but its original request was not
   available to prove exactly which event caused it.

   Fix: ordinary text replies may finish while a window is backgrounded. Pending
   editing/professional operations still cancel when hidden; explicit Stop,
   workspace closing and account/scope changes remain guarded. Cancellation now
   has a useful reason. Microphone/Hands-Free hidden-page suspension is unchanged.

5. Authenticated transport errors lost HTTP status in the conversation layer.
   ZorifiProductionBridge throws an Error carrying status/code for a failed
   authenticated request. ConversationEngine caught it but discarded status,
   so an expired session/rate response could be reduced to the generic
   'online AI service could not answer this request'. Storage/order errors also
   lacked useful user-facing distinctions.

   Fix: retain status and code, with safe specific messages for private storage,
   pending turns and invalid conversation signatures. No raw upstream details,
   tokens or fake offline-success responses are shown.

6. Unnecessary clarification for the actual typed request 'wrok on this project'.
   That request fell outside the verified professional delegation recognizer.
   'Work on this project' and 'Edit this video' now reach the existing evidence-
   based, authorized professional pipeline; the observed typo is normalized.
   Questions and review-only/no-edit instructions remain excluded. The real
   proactive-edit browser regression now exercises that exact typed request.
